### File management 
File management is used to manage the file content, lets see some commands that we use to manage the files.

`cat`: print a whole file
Short for "concatenate." It dumps file contents to the terminal, and can join several files together.

```
cat notes.txt              # show the file
cat a.txt b.txt            # show both, one after another
cat a.txt b.txt > all.txt  # combine into a new file
cat -n app.log             # show with line numbers
```

`less`: read a file page by page
Opens a file in a scrollable viewer without loading it all at once, so it's good for large files and logs.
```
less /var/log/syslog
```

`head`: show the start of a file
Prints the first 10 lines by default

```
head app.log        # first 10 lines
head -n 20 app.log  # first 20 lines
```

`tail`: show the end of a file
Prints the last 10 lines by default. This is the go-to for logs, since the newest entries are at the bottom.

```
tail app.log
tail -n 50 app.log   # last 50 lines
tail -f app.log      # follow: print new lines as they're written
```

`find`: locate files by name, type, size, or age
Searches the directory tree by file attributes, not contents.

```
find . -name "*.log"            # files ending in .log under current dir
find /etc -type f -name "*.conf"  # only regular files
find . -type d -name "node_modules"  # directories only
find . -size +100M              # files larger than 100 MB
find . -mtime -1                # modified in the last 24 hours
find . -name "*.tmp" -delete    # find and delete (be careful)
find . -name "*.sh" -exec chmod +x {} \;   # run a command on each match
```

`grep`: search inside files for text
Finds lines that match a pattern
```
grep "error" app.log          # lines containing "error"
grep -i "error" app.log       # case-insensitive
grep -n "error" app.log       # show line numbers
grep -v "debug" app.log       # invert: lines NOT matching
grep -r "TODO" ./src          # search recursively through a directory
grep -c "error" app.log       # count matching lines
grep -E "error|fail" app.log  # regex: error OR fail
grep -A 3 -B 3 "error" app.log  # 3 lines after and before each match
```
